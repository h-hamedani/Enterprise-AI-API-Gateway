# M4-P1C — internal protected lifecycle

Baseline: `eadb46c`. No public route, new lifespan worker, HTTPX invocation, credential injection, body-forwarding implementation, response stream, telemetry writer, outcome logger, metrics adapter, migration, or OpenAPI change is introduced.

`RequestLifecycle` is single-use and receives the existing P1B resolver and M3 recovery-aware facades. Its required `Hooks` describe the unfinished policy-resolution, bounded body, deterministic preparation, execution, and delivery integration seams. There are deliberately no default successful body/executor/delivery stubs. Tests supply synthetic executors; those are not production HTTP forwarding. Resolved policy inputs are tenant/resource-validated, frozen into tuples, and ordered API_KEY → ROUTE → SERVICE before the existing cumulative M3 calls. A real policy configuration owner must supply all applicable enabled policies; this slice does not claim a completed Normal API policy repository.

## Ownership and ordering

One scope owns one immutable P1B/R18 resolution, one original provenance-aware concurrency handle, one renewal worker, one circuit handle, one execution task, one receive task when needed, one applicable circuit-completion task, and one cleanup task. Resolution establishes R25 attribution eligibility but does not write a request record. R7A ordering is resolution → policy inputs → rate → acquire → body hook → preparation hook → circuit → execution hook → delivery hook → terminal cleanup. No body receive starts before acquisition. Rate denial carries the existing rejecting retry delay; concurrency denial invents no retry delay. No refund, second acquire, backend substitution, retry, or probe-abort operation exists.

The sole synchronous event-loop decision fence records either a definitive upstream result or an earlier local terminal decision. Upstream completion does not end downstream lifetime or renewal. A later disconnect/loss stops delivery without rewriting upstream classification; circuit completion starts once from the recorded result, remains request-owned, and is joined before return. M3 APPLIED/STALE/UNKNOWN_HANDLE results are retained unchanged. Before any definitive result, cancellation causes NO_COMPLETION, including after a HALF_OPEN claim; existing M3 probe expiry remains authoritative. A second outcome, terminal decision, or commitment notification cannot initiate another action.

## Renewal and cancellation

R8 uses the existing TTL and an injectable monotonic clock: dispatch-time anchor, renewal at T/3, one UNKNOWN retry at T/2, and the original 2T/3 safety horizon. The confirmed anchor/deadline are request-local state, not worker-only variables. Protected stage transitions, post-await checks, upstream/timeout observations and downstream commitment independently check that deadline. A preparation stall cannot reach circuit or dispatch merely because the worker has not run. Only a confirmed true renewal observed while active and before the old horizon publishes a new window, before any awaited timer cleanup. UNKNOWN/false never extend it. False means definitive loss; dependency failure means UNKNOWN. Null ownership has neither worker nor release. Release false/failure cannot replace the selected client/circuit result.

`run()` now requires a registered `LifecycleScope` from the process-local `LifecycleSupervisor`, replacing the Event-only F1 boundary under the committed M4-P1C-R1 contract. Registration and admission closure are synchronous on one owning event loop; cross-loop authority is rejected. The runner is launched synchronously so cancellation before its first instruction remains supervised and establishes cleanup grace. One authoritative monotonic clock supplies request and process deadlines; earliest cutoff wins. First terminal cancellation or successful cleanup activation sets the request deadline, not upstream completion alone. Repeated cancellation cannot reset it. Expiry is latched and deadline-driven even with notification unset; set/observe/clear cannot undo it. Every finalizer join shares that finite cutoff. Renewal and its operations must stop before the one original-handle release; an independently stalled executor finalizer cannot block an eligible release.

Python cannot forcibly terminate a coroutine that suppresses cancellation. At cutoff, cleanup is explicitly incomplete. Scope task references and the lifecycle owner transfer to the supervisor's process-local residual set before deregistration. Eventual completion/exception observation updates factual release accounting but cannot revive execution, rewrite outcomes or trigger retries. `release_obligation` distinguishes none, not attempted, attempted/unconfirmed, confirmed false and confirmed success. Existing M3 release results authoritatively distinguish true from false (including absent/stale ownership); an exception, including protocol error after dispatch, establishes neither backend outcome. Such attempts remain unconfirmed and retained, without retry. If renewal remains unfinished, release is not raced; the unmade obligation remains retained and M3 expiry is the safety net. A release interrupted at cutoff is not reported confirmed. Cleanup-task failure, unresolved release, or unresolved applicable circuit completion prevents `cleanup_complete=True` even with no pending child tasks. There is no distributed handoff, task-kill primitive or new M3 algorithm.

## Approved configuration and server integration

`LIFECYCLE_GRACE_TIMEOUT_SECONDS=30` is the explicitly approved initial deployment value, configured in `.env.example` and both development launchers. It is not an application default or fallback. Settings omission preserves non-managed startup, while invalid supplied values fail validation; the managed server rejects omission. The development launchers use `python -m app.server`. Its Uvicorn adapter latches supervisor shutdown before drain and bounds the combined server shutdown operation by the same process deadline. Application lifespan creates/reuses one supervisor, drains supervised uses before dependency closure and applies the remaining process budget to resource closure. No second lifespan grace window is granted. Direct stock Uvicorn invocation remains a non-managed launch path and is not evidence of R1 server compliance.

An already-expired server cutoff still requests listener closure and cancels/retains server-owned and managed request tasks. It does not start a fresh grace window or erase skipped lifespan obligations. `close()` requested and `wait_closed()` confirmed are tracked separately; a nonblocking listener-close observation task remains owned if it cannot finish by cutoff. Forced process shutdown, a blocked event loop or cancellation-resistant Python tasks can prevent timely resource closure; unresolved operations remain observable while the process lives. This implementation does not claim forcible process termination. Configured resource closure not reached before cutoff is explicitly reported as unclosed rather than retried. A clock-contract failure conservatively ends waiting rather than manufacturing a new deadline.

## Receive and timeout seams

`ReceiveOwner` alone calls ASGI receive. At the body stage it hands off one message at a time, with acknowledgement before another body read. Normal final `http.request` establishes completion; only then does it continue observing disconnects. A pre-body disconnect already known to the server enters the same cancellation gate without reading ahead. There is no pre-admission body pump. Unknown receive failure is internal, never a fabricated empty tail. The body hook still owns R6/R15 size/framing validation and bounded materialization; this P1C seam is not a complete body guard.

The explicit R10 timeout-observation hook accepts phase categories, implements the frozen simultaneous-observation precedence, and competes at the same decision fence. It creates no real HTTPX deadlines. Pool/pre-response timeouts are NO_COMPLETION; verified connect/write/read timeouts are FAILURE. Pre-response observations are ignored after commitment. The future transport must call the hook only for actual established phase timeouts and must provide the R16/R17 commitment/definitive-outcome evidence. No headers/first-byte observation fabricates clean completion.

`before_downstream_commit()` is the protected pre-send permission check. `committed_downstream()` is the factual observation after successful response-start delivery; expiry during that await terminates remaining delivery but cannot erase commitment or authorize a second error envelope. These are internal adapter seams, not an implemented ASGI response writer.

## Evidence and deferred work

Deterministic tests use Events and a manually advanced clock, not sleeps as correctness proof. Supervisor tests cover finite unset-notification cutoff, latching, registration orderings, cancellation before first execution, residual observation, and pending renewal/release/finalizers. F3 regressions first reproduced all three review failures, then verified already-expired mandatory actions, actual M3 release protocol uncertainty and cleanup failure before release. Real PostgreSQL/Redis tests use P1B authentication and certified projections with actual M3 facades, independent tenants, capacity contention, local degraded mode and original-backend completion after a mode change. A real application lifespan test checks that supervised request use completes before dependencies close.

Opt-in `M4_F3_SERVER_ACCEPTANCE=1` runs real child processes executing `app.server`'s `__main__` via `runpy`, with test-only lifecycle observations. Both normal and already-expired paths passed on Windows using hidden consoles and supported Ctrl+Break. Test-owned PostgreSQL/Redis containers use dynamic loopback ports, no shared volumes or application data, and are removed afterward. Health live/ready respond before signalling; activation precedes Uvicorn drain in the normal case, listener closure is confirmed, application lifespan exits and the child exits zero with the listener unavailable. A test-owned prior signal handler observes Uvicorn's restored-handler chaining without OS signal re-termination; this is not a claim about default-handler exit codes. The expired variant injects a clock offset only after shutdown activation (G remains 30; system time is unchanged), proves no fresh window and reports skipped lifespan cleanup as unfinished. External watchdogs are test safety bounds, not Gateway policy. Linux has a SIGTERM branch but was not executed in this Windows run. The initial console helper needed an acknowledgement fence before detachment; no product signal policy changed.

This is minimal real process/signal/health evidence, not long-running upstream/streaming shutdown acceptance. It does not prove real transport timeouts or streaming/backpressure. Policy resolution, body/framing, secure transport, secret injection, delivery and R25/R26/R27 observers remain deferred before public proxy exposure. Admin overlap validation remains separate.

The lifecycle now consumes the accepted guarded facade with F7's internal cleanup-scope context. Producing timestamps, expected/unexplained suppression, independent unresolved attempts and deferred resource evidence remain request-owned. Existing supervisor accounting retains unresolved obligations.
