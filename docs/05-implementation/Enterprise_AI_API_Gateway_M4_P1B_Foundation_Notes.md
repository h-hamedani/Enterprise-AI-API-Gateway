# M4-P1B — internal resolution foundation

Baseline: `b80a1d3`. This slice exposes `app.state.normal_api_resolver` when the existing credential HMAC configuration is available. It registers **no public endpoint**: successful internal resolution does not execute, admit traffic, read a body, claim R25 persistence, or dispatch upstream.

The caller supplies the canonical middleware request ID. `resolve(scope, request_id=...)` authenticates Bearer `gw_` using the existing HMAC/verifier infrastructure, joins the owning Application/Tenant, and reads INVOKE permissions. It uses the frozen credential-status strict mode (TTL=0): authoritative credential/permission reads on each invocation, with no general configuration cache authorizing a credential. Authentication failures precede path/configuration disclosure. SERVICE grants cover the service; ROUTE grants cover only their concrete method-specific route identity. Cross-tenant references cannot confer authority.

After authentication, raw-path validation produces one canonical semantic segment tuple and its derived encoded remaining-path serialization. It never reinterprets `scope["path"]` as routing input; when present, that decoded field is checked only for consistency. Query bytes are not parsed. Percent decoding happens once per input segment. Persisted static pattern text is matched exactly against those established semantic segments; it is not percent-decoded or Unicode-normalized. Whole named parameters match one nonempty segment, with no wildcard/catch-all DSL. The encoded remaining path is serialization of the same identity, not a second interpretation or a constructed upstream request.

The authenticated tenant is lazily registered with P1A. Registration/capture use a try-now `asyncio.timeout(0)` scope: an already contended tenant lock returns the safe unavailable result instead of waiting on reconciliation. Unregistered/pending/dirty/uncertified state returns existing 500 `gateway_internal_error`. No inline reconciliation, task-per-request, retry queue or Service/Route persistence fallback exists. The existing managed reconciler owns initialization and repair on its established lifecycle/cadence. Repeated requests do not reset an existing registration. One successful capture is immutable and can finish selection after later local invalidation, as R18 permits.

Resolution uses one tenant/service-scoped executable path set. R19 empty set is 404; absent method is 405 with fixed-order `GET, POST, PUT, PATCH, DELETE` inventory. Explicit `GatewayHttpError` preserves 405/Allow without the generic framework HTTP-exception remapping. HEAD/OPTIONS/TRACE/CONNECT never resolve to executable routes. No CORS grant or slash redirect is implemented. Required configuration is validated; the R6 effective body limit is captured as the minimum of deployment and persisted service limits, without reading/buffering a body.

R1 and the M4 execution pack require **no runtime winner** when multiple records match path and method. Stored priority does not resolve overlap. Such a request fails with safe 500, including real database-valid overlapping rows. This keeps P1B safe without silently changing Admin acceptance.

## Separate Admin implementation gate

The Physical DB / Alembic Spec V1.2 section 8.2 requires RouteOverlapValidator on create/update/enable before configuration-version increment. No implementation is present in the repository. `app/control_plane/normal_api_registry.py` directly persists create/patch Route values, and `app/api/control_plane/normal_api_registry.py` coordinates the existing mutation/version publication. Implementing that missing Admin gate remains mandatory separate work before claiming complete M4 contract compliance. P1B does not modify these endpoints, OpenAPI, schema or migrations. R22 duplicate-slash and R23 NFC Admin validation also remain separately scoped; incompatible legacy patterns do not become executable or poison unrelated valid routes.

## Acceptance and limits

Tests use raw ASGI dictionaries (including inputs a high-level URL client could normalize), test-only FastAPI registration with actual request-ID/error middleware, and isolated PostgreSQL tenants for real credential/status/permission checks and persisted overlap. Body receive, M3 facade methods and HTTPX send are forbidden in the ASGI probe. These are not public proxy, transport, streaming/backpressure, or full R25/R26/R27 acceptance tests. No managed credential decryption/injection or production DNS/SSRF/TLS connector is added. P1C must integrate protected admission/lifecycle before any production forwarding endpoint becomes reachable.
